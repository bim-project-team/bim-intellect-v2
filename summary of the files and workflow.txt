Kimi: ## BIM-Intellect — Full Pipeline Summary

BIM-Intellect is a **hybrid RAG system** that combines **regulatory text retrieval** (Mabhas 15) with **graph-based building data retrieval** (IFC → Neo4j) to answer compliance questions with citations to both legal clauses and specific building elements.

---

## Architecture Layers

```
┌─────────────────────────────────────────────────────────────┐
│  FRONTEND  (templates/index.html + static/app.js + style.css) │
│  Chat · Pipeline · Corpus Upload · Results                    │
├─────────────────────────────────────────────────────────────┤
│  API  (api/routes.py)                                        │
│  HTTP endpoints → orchestrates all backend modules            │
├─────────────────────────────────────────────────────────────┤
│  RAG  (rag/)                                                 │
│  Chunk → Embed → Store (Chroma)  |  Retrieve → Generate (LLM)│
├─────────────────────────────────────────────────────────────┤
│  GRAPH  (bim_graph/)                                         │
│  IFC → CSV → Neo4j  |  Clash Detection  |  Cypher RAG       │
├─────────────────────────────────────────────────────────────┤
│  DATA  (dataset/ + nodes.csv + edges.csv)                    │
│  IFC models · Regulation PDFs                                 │
└─────────────────────────────────────────────────────────────┘
```

## File-by-File Responsibilities

### Entry Point & Infrastructure

| File | Responsibility |
|------|----------------|
| **`main.py`** | FastAPI application bootstrap. Mounts the API router (`api/routes.py`) and serves static files (`static/`) and templates (`templates/`). |
| **`docker-compose.yml`** | Spins up Neo4j (with APOC plugin) and any other services. Defines the graph database environment. |
| **`requirements.txt`** | Python dependencies: FastAPI, Neo4j driver, ChromaDB, OpenAI SDK, pypdf, pandas, python-ifcopenshell, etc. |
| **`notebook.ipynb`** | Exploration / prototyping notebook for ad-hoc graph queries, data inspection, and experimentation. |

---

### IFC Extraction (Pre-Graph)

| File | Responsibility |
|------|----------------|
| **`extract_graph.py`** | Parses `.ifc` files using IfcOpenShell. Extracts every element's metadata (ID, IFC type, name, storey, bounding box) into `nodes.csv` and spatial/aggregation relationships into `edges.csv`. |
| **`nodes.csv`** | Output of `extract_graph.py`. One row per building element with geometry and classification data. |
| **`edges.csv`** | Output of `extract_graph.py`. One row per relationship (AGGREGATES, CONTAINS, BOUNDS, PORT_OF) linking two element IDs. |

---

### Graph Layer (`bim_graph/`)

| File | Responsibility |
|------|----------------|
| **`config.py`** | Centralized constants: Neo4j URI/credentials, CSV file paths, batch sizes, default IFC path. |
| **`neo4j_client.py`** | Thin wrapper around the official Neo4j Python driver. Provides `run()`, `run_batched()`, and context-manager lifecycle (`with Neo4jClient() as client:`). |
| **`load_to_neo4j.py`** | Bulk-loads `nodes.csv` / `edges.csv` into Neo4j using batched `UNWIND` Cypher (not `LOAD CSV`). Uses `MERGE` for idempotency and `apoc.create.addLabels` to tag each node with its IFC type as a queryable label (e.g., `:IfcWall`). |
| **`clash_pipeline.py`** | Runs AABB (axis-aligned bounding box) clash detection and clearance violation checks against the Neo4j graph. Writes detected issues back as `:CLASHES_WITH` relationships. |
| **`diagnose_load.py`** | Debugging utility. Identifies which edge rows failed to load (dangling source/target IDs) so you can fix extraction scope. |
| **`cypher_generator.py`** *(new)* | **NL → Cypher.** Uses GPT-4o-mini to convert natural language questions into read-only Cypher queries. Has safety rails: blocks `DROP/DELETE/CREATE/MERGE` and rejects non-read keywords. |
| **`graph_retriever.py`** *(new)* | **Graph RAG step.** Takes a question, calls `cypher_generator.py` to get Cypher, executes it via `neo4j_client.py`, and formats records into a human-readable context string + structured source metadata for the LLM. |

---

### RAG Layer (`rag/`)

| File | Responsibility |
|------|----------------|
| **`openrouter_client.py`** | Shared OpenRouter client (OpenAI-compatible SDK). Handles API key validation, retry logic with exponential backoff, and error classification (`LLMConfigError` vs `LLMRequestError`). Used by embedder, retriever, orchestrator, and cypher generator. |
| **`chunker.py`** | Slices a regulation PDF into overlapping text chunks. Each chunk gets a traceable ID (`doc_id-p{page}-c{index}`) and a best-effort `clause_id` extracted via regex for citation integrity. |
| **`embedder.py`** | Embeds chunks via OpenRouter (`text-embedding-3-small`) and stores them in a local **ChromaDB** persistent collection. Batches embedding requests to stay within provider limits. |
| **`retriever.py`** | **Legacy vector-only RAG.** Queries Chroma for similar chunks, builds a citation-tagged context block, and calls GPT-4o-mini with a strict "cite every claim" system prompt. Also provides `ChatSession` for multi-turn conversations. |
| **`prompts.py`** *(new)* | Centralized system prompts: **Router** (decides vector vs graph vs both), **Cypher Generator** (schema-aware NL→Cypher), and **Combine** (synthesizes regulation + graph context into one answer). |
| **`orchestrator.py`** *(new)* | **The brain.** Three-step pipeline: (1) **Route** — LLM analyzes the question and decides which sources are needed; (2) **Retrieve** — fetches from Chroma and/or Neo4j in parallel; (3) **Generate** — sends combined context to GPT-4o-mini once, producing a synthesized answer with mixed citations. |

---

### Frontend (`templates/` + `static/`)

| File | Responsibility |
|------|----------------|
| **`index.html`** | Four-tab SPA: **Chat** (hybrid Q&A with bubbles & source tags), **Pipeline** (IFC ingest + console log), **RAG Corpus** (PDF drag-and-drop upload + Chroma status), **Results** (clashes/violations table). |
| **`style.css`** | Monochrome black & white theme. Georgia serif headings, Courier monospace data/console. Responsive chat layout with sidebar on desktop. |
| **`app.js`** | All frontend logic: tab navigation, chat message rendering with typing indicators, example-question buttons, drag-and-drop PDF upload, corpus status polling, pipeline console logging, and results table rendering. |

## End-to-End Data Flow

### 1. Ingest Regulations (RAG Corpus)
```
dataset/sources/mabhas-15-elvators-stairs.pdf
    │
    ▼
/rag/upload  →  chunker.py  →  list[Chunk]
    │
    ▼
embedder.py  →  OpenRouter embeddings  →  ChromaDB (./chroma_db / "regulations")
```

### 2. Ingest Building Model (Graph)
```
dataset/210_King_Merged.ifc
    │
    ▼
extract_graph.py  →  nodes.csv + edges.csv
    │
    ▼
/api/ingest  →  load_to_neo4j.py  →  Neo4j (:Element {id, ifcType, name, ...})
    │
    ▼
/api/analyze  →  clash_pipeline.py  →  (:Element)-[:CLASHES_WITH]-(:Element)
```

### 3. Ask a Question (Hybrid RAG)
```
User types: "Does the ground floor comply with Mabhas 15 stair requirements?"
    │
    ▼
/api/ask  →  orchestrator.py
    │
    ├──► Route (LLM) → needs_vector=true, needs_graph=true
    │
    ├──► Vector path: embedder.query_similar() → Chroma chunks
    │
    └──► Graph path: graph_retriever.ask() → cypher_generator → Neo4j → records
    │
    ▼
Combine prompt → GPT-4o-mini
    │
    ▼
Answer: "The ground floor has 2 stairs (Element ID 0xAB12...). 
         Mabhas 15 [Clause 4.2] requires a minimum width of 1.2m..."
    │
    ▼
Frontend renders bubbles + source tags (Clause 4.2 | IfcStair Main Stair)
```
